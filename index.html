Sistema de Compra, Venda e Estoque

Loja de roupas online · Desafio CRUD Completo 2026 · Modelagem UML para construção em equipe

Uma vendedora recebe pedidos pela internet e precisa de um sistema de terminal para cadastrar produtos e clientes, registrar vendas, repor estoque (compras) e acompanhar o caixa. Cada dupla constrói um pedaço; o sistema só funciona quando as peças se encaixam.

🐍 Python puro 🧩 Só funções + dicionários 🚫 Sem classes, sem bibliotecas, sem arquivos 💻 Roda no terminal (prompt) 👥 6 times · 1 sistema

2. Times e responsabilidades

Cada time entrega um arquivo .py contendo apenas funções. Nenhuma função guarda dados: tudo que muda é recebido por parâmetro.

Time 1 Prints estáticos (Interface)

Arquivo: interface.py · prefixo exibir_

Tudo o que aparece na tela: cabeçalho, menus, tabelas, recibo, mensagens de erro/sucesso. Não lê teclado e não altera dicionários.

  • exibir_menu_principal()
  • exibir_tabela_produtos(produtos)
  • exibir_recibo(venda, produtos, clientes)
  • exibir_mensagem(texto, tipo)
Depende de: Time 4 (formatar_moeda) e Time 5 (situacao_produto)

Time 2 Coleta de dados

Arquivo: coleta.py · prefixos ler_, coletar_

Todos os input() do sistema, com validação e repetição até o usuário digitar algo válido. Devolve valores prontos (int, float, str, dict).

  • ler_inteiro(mensagem, minimo)
  • ler_decimal(mensagem, minimo)
  • coletar_dados_produto() → dict
  • coletar_item() → {codigo, quantidade}
Depende de: Time 1 (exibir_mensagem)

Time 3 Cadastro de dados

Arquivo: cadastro.py · prefixos cadastrar_, registrar_, buscar_

Guarda e localiza registros nos dicionários. Gera códigos automáticos. É a única porta de entrada para criar registros.

  • gerar_codigo(dicionario)
  • cadastrar_produto(produtos, dados)
  • registrar_venda(vendas, venda)
  • buscar_produto(produtos, codigo)
Depende de: ninguém (módulo base)

Time 4 Manipulações matemáticas

Arquivo: calculos.py · prefixos calcular_, formatar_

Toda conta do sistema: subtotal, total, desconto, troco, lucro, margem, valor do estoque, resumo financeiro. Funções puras: recebem, calculam, devolvem.

  • calcular_total_itens(itens, produtos)
  • aplicar_desconto(valor, percentual)
  • calcular_lucro_venda(itens, produtos)
  • formatar_moeda(valor) → "R$ 1.234,50"
Depende de: Time 3 (buscar_produto)

Time 5 Controle de estoque

Arquivo: estoque.py · prefixos verificar_, baixar_, repor_, relatorio_

Quantidade de cada produto: confere disponibilidade, dá baixa na venda, repõe na compra, aponta produtos em falta e esgotados.

  • verificar_disponibilidade(produtos, codigo, qtd)
  • baixar_estoque_itens(produtos, itens)
  • repor_estoque_itens(produtos, itens)
  • relatorio_estoque(produtos, minimo)
Depende de: Time 3 (buscar_produto)

Time 6 Atualizações e Integração

Arquivos: atualizacao.py e main.py · prefixos atualizar_, remover_, fluxo_, menu_

Altera e remove registros, controla o caixa e monta os fluxos completos (venda, compra, relatórios) ligando as funções dos outros times no menu principal.

  • atualizar_produto(produtos, codigo, campo, valor)
  • remover_produto(produtos, codigo)
  • fluxo_realizar_venda(sistema)
  • executar_sistema(sistema) — laço principal
Depende de: todos os times

3. Regras do desafio e convenções

Limites técnicos e combinados de nomenclatura para o código de todos encaixar.

Limites técnicos

PodeNão pode
Funções (def), parâmetros e return
Dicionários, listas simples, strings, números, booleanos
if / elif / else, for, while
input(), print(), f-strings
import dos arquivos dos outros times 		Classes (class) e orientação a objetos
Bibliotecas externas (pandas, rich, etc.)
Salvar em arquivo ou banco de dados (os dados vivem só na execução)
Variáveis globais alteradas dentro de funções (global)
Interface gráfica — é tudo no terminal

Convenções obrigatórias

  • snake_case para funções e variáveis: cadastrar_produto, preco_venda.
  • Verbo no infinitivo no início do nome, usando o prefixo do time (ver cards acima).
  • Dicionário sempre por parâmetro. Nenhuma função usa variável global. Quem precisa alterar produtos recebe produtos.
  • Retornos padronizados: operações devolvem True/False; buscas devolvem o dicionário encontrado ou None; cadastros devolvem o código gerado.
  • Códigos são inteiros gerados por gerar_codigo() (maior código + 1, começando em 1).
  • Dinheiro é float, percentual de desconto é número de 0 a 100.
  • Uma função, uma tarefa. Se passou de ~25 linhas, provavelmente são duas funções.
  • Docstring curta em toda função: o que faz, o que recebe, o que devolve.
A regra de ouro: só o Time 6 chama funções de todos os outros. Os demais times chamam no máximo um ou dois módulos vizinhos (ver mapa de dependências). Isso evita o sistema virar um novelo.

Descrição dos casos de uso principais

Caso de usoPré-condiçãoFluxo principal (resumo)Pós-condição
Cadastrar produto — Vendedora informa nome, categoria, tamanho, cor, preço de custo, preço de venda e quantidade inicial. Sistema gera código e salva. Produto existe em produtos com código novo.
Cadastrar cliente — Vendedora informa nome, telefone e cidade. Sistema gera código e salva. Cliente existe em clientes.
Registrar venda Existe ao menos 1 cliente e 1 produto com estoque. Escolhe cliente → adiciona itens (código + quantidade) conferindo disponibilidade → calcula total → desconto opcional → forma de pagamento → confirma. Venda salva em vendas, estoque baixado, caixa somado, recibo exibido.
Registrar compra (reposição) Produto já cadastrado. Informa fornecedor → adiciona itens (código + quantidade) → calcula total pelo preço de custo → confirma. Compra salva em compras, estoque reposto, caixa subtraído.
Consultar estoque — Sistema lista produtos com quantidade, situação (OK / BAIXO / ESGOTADO) e valor total parado em estoque. Nada muda.
Atualizar dados Registro existe. Escolhe produto/cliente pelo código → escolhe campo → informa novo valor → confirma. Campo alterado no dicionário.
Remover dados Registro existe. Escolhe pelo código → sistema mostra o registro → pede confirmação → remove. Chave removida do dicionário.
Ver relatório financeiro — Sistema soma vendas, compras, calcula saldo, lucro e ticket médio. Nada muda.

13. Plano de integração

Como sair de seis arquivos soltos para um sistema que roda. Em etapas, cada uma com algo testável.

  1. Contrato fechado (todos) — cada time lê a sua tabela da seção 12 e o esqueleto em esqueleto/. Dúvidas sobre nome, parâmetro ou retorno são resolvidas antes de codar. Depois disso, mudar o contrato exige avisar quem depende.
  2. Base de dados de teste (todos) — todos usam o mesmo dados.py com criar_sistema(). Assim os testes de cada time batem com os dos outros.
  3. Implementação isolada (cada time) — cada dupla preenche suas funções e testa num bloco if __name__ == "__main__": no fim do próprio arquivo, chamando as funções com o dicionário de exemplo. Time 3 e Time 4 primeiro, pois são a base.
  4. Integração 1 — Cadastro e listagem — Time 6 liga menu + fluxo_cadastrar_produto + fluxo_listar_produtos. Envolve T1, T2, T3, T4 e T6. Meta: cadastrar e ver na tabela.
  5. Integração 2 — Venda completa — fluxo_realizar_venda com estoque e recibo. Envolve todos. Meta: o cenário da seção 11 até o passo 5.
  6. Integração 3 — Compra, atualizar, remover, relatórios — fecha o CRUD e os relatórios. Meta: cenário da seção 11 completo.
  7. Teste cruzado — cada time testa o fluxo de outro time tentando quebrá-lo (letra onde é número, código inexistente, quantidade zero, Enter vazio). Bugs vão para o time dono da função.
  8. Apresentação — cada time apresenta 1 função sua e 1 função de outro time que ela chama ou que a chama, explicando o encaixe.

Como rodar

# dentro da pasta com os 8 arquivos .py
python main.py

14. Sugestões de melhoria na divisão dos times

Ajustes pensados a partir do mapa de dependências.

Separar "Integração" de "Atualização"

O Time 6 hoje acumula o CRUD de atualizar/remover e o main.py, que é a parte que mais quebra. Se houver gente suficiente, um Time 7 — Integração e Testes cuidando só de main.py e do cenário de teste da seção 11 deixa o sistema mais estável. Alternativa: o papel de "integrador" rotaciona entre os times a cada etapa.

Venda e compra pertencem à integração

No quadro, "venda/compra" era uma bolha separada. No modelo, elas não são um módulo: são fluxos que combinam Coleta + Cadastro + Estoque + Cálculos + Interface. Por isso ficaram em main.py como fluxo_realizar_venda e fluxo_realizar_compra.

Cadastro é a base: comece por ele

buscar_produto é usada por três times. Sugestão: o Time 3 entrega gerar_codigo, buscar_produto e buscar_cliente no primeiro dia, para desbloquear Estoque e Cálculos.

Stubs para ninguém ficar parado

Enquanto a função real não existe, o Time 6 usa uma versão falsa que só devolve um valor fixo (ex.: return True). Assim o menu já roda no primeiro dia e os times trocam a função falsa pela real quando ficar pronta.

Venda sem cliente cadastrado

Extensão simples: aceitar código 0 como "Consumidor final" em fluxo_realizar_venda. Evita travar a venda quando a vendedora não quer cadastrar o cliente.

Desafio extra (fora do escopo base)

Para quem terminar antes: busca de produto por nome (buscar_produto_por_nome), troco para pagamento em dinheiro (calcular_troco) e ranking de produtos mais vendidos a partir de vendas. Tudo continua só com funções e dicionários.
